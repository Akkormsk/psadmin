# Бэклог: параметры ТЗ по этапам маршрута

Дата: 2026-09-27.

## Проблема

Сейчас чекбоксы строк ТЗ (`requirement_selection`) — один общий список на
весь расчёт позиции. Он не зависит от того, какой этап маршрута сейчас
активен.

Пример: «футболка с нанесением». На этапе поиска самой футболки должны
быть включены только параметры футболки (размер, состав, цвет) и выключены
параметры нанесения (техника, количество цветов, расположение). На этапе
расчёта нанесения — наоборот.

Сейчас пользователь либо держит все параметры включёнными сразу (агент
шага 6 проверяет по карточке товара характеристики, которые к этой карточке
не относятся), либо вручную выключает и включает чекбоксы между этапами,
и это легко забыть сделать.

## Что нужно решить перед реализацией

- Как выглядит вменяемый UI: чекбоксы ТЗ внутри каждого раскрытого этапа
  (дублирование одного списка N раз) или один список сверху с отметкой
  «к какому этапу относится» на каждой строке?
- Кто размечает, к какому этапу относится строка ТЗ: агент при разборе
  ТЗ (шаг 1) сразу пробует привязать строку к типу этапа, или это делает
  агент построения маршрута (`routes.py`) уже после того, как маршрут
  собран?
- Совместимость: `requirement_selection` сейчас плоский список — менять
  его на структуру `{этап: [...]}` значит трогать формат сохранённой
  гипотезы и, возможно, старые подтверждённые примеры/уроки.
- Как ведёт себя строка ТЗ, которая нужна нескольким этапам сразу
  (например «количество» — для футболки и для нанесения одновременно).

## Статус

Не начато. Обсудить архитектуру и UX с пользователем перед тем, как
писать код.
