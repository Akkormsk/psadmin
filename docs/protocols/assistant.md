## 9. Окно ассистента (структура сверху вниз)

1. Заголовок позиции.
2. `<details>` «Требования позиции» — свёрнут по умолчанию. Внутри отдельно
   показаны строки исходного ТЗ и «Мои уточнения» из ответов текущего заказа.
   У каждой строки ТЗ чекбокс: снятая = «не участвует в подборе». Начальное состояние — из
   `requirement_selection`. После расчёта — кнопка «Учесть и пересчитать» и
   плашки постоянных правил `RequirementSkipRule` с ×.
   Явные характеристики из названия сначала показываются в нижней панели
   «Найдено в названии» и попадают в «Мои уточнения» только после подтверждения.
3. Блок «Технологический маршрут»: обоснование текстом, вертикальная колонка
   пронумерованных шагов, каждый — раскрывающийся на месте `<details>`.
   - Шаг «Закупка готового изделия»: плашки («Учтён прошлый опыт», «ИИ
     убрал: N»), карточки (раскрывающийся список ✓/✗/? по ТЗ), «Ваши
     корректировки» + поле обратной связи. Первый по подбору с ценой — «В
     расчёте · авто».
   - Все шаги свёрнуты по умолчанию. Раскрытие не запускает поиск.
   - Внутри этапа — «Исправить этап»; внизу маршрута — «Исправить маршрут».
4. Блок «Рассчитанная часть стоимости» — сразу после маршрута, когда есть цена.
5. Нижняя фиксированная панель: себестоимость за ед./тираж + `↺` («Начать
   заново») + «Принять и обучить».

Точки кода фронта: `templates/tenders/home.html::openRequirements` (каркас
окна), `::trainingDialogueHtml` (маршрут + блоки шагов),
`::feedbackWidgetHtml` (обратная связь), `::bindProductionControls`.

Видимость/сроки/профиль используют общий selector экрана. Истёкшие тендеры/документы архивируются, не уничтожаются. Ручной импорт 19-значного номера идемпотентен, не переоткрывает обработанные записи и не создаёт placeholder при ошибке. Торги сохраняют реальные места/источник; наша ставка не исчезает за пределами первых десяти участников. Исполнение после победы — отдельный незавершённый контур, finance.OrderRecord не доказывает его готовность.

## 12. Общий ассистент, знания и backlog

### M3 и операции пользователя

Актуальный TEST `assistant_agent.py` использует Chat Completions Function Calling, app-owned capabilities и `assistant_read.py`; старые JSON next_step/assistant.navigate-графы не восстанавливать по историческим инструкциям. Код plan/ask/finish/cancel, verified references и compact memory не является новой live-приёмкой чата в рамках уборки.

- READ строится из Django metadata и проверяется ORM validator; SQL от LLM запрещён. `verbose_name`, help_text, choices, права/связи и общий selector экрана определяют смысл, не phrase-specific hardcode.
- ACTION объявляется приложением и использует тот же callable, что UI. Входы/права/ссылки проверяются до preview и снова при исполнении. Подтверждение — штатная кнопка, не текстовое «да». Повтор/stale/отмена не создают повторную запись.
- References берутся из реального READ/сохранённых verified sources. «Из них» сохраняет исходный набор даже при пустом результате; нельзя заменить его global search. Нет оснований — уточнение в бизнес-терминах без просьбы назвать internal ID.
- Незавершённое подтверждение и аргументы сохраняются; законченные tool payload не повторяются бесконечно. Диалог, debug, lessons и confirmed knowledge — разные scopes. Наблюдаемая трасса не является скрытым рассуждением модели.
- Возможность сайта не становится автоматическим разрешением AI: права/preview/audit обязательны. Webhooks/фоновые/технические endpoints не публикуются как пользовательские макрофункции. Telegram — будущий адаптер общего backend без второй логики.

### Контроль полноты библиотеки — CODE_ONLY, 2026-11-28

Добавлен общий аудит пользовательских операций без списков отдельных функций. Он находит серверные изменения, варианты одного действия и новые ссылки из адресов, шаблонов и JavaScript; затем проверяет реальный исполнитель по библиотеке ассистента. Допустимо только опубликованное действие или явное исключение с причиной и существующим исполнителем. Проверка сравнивает feature-ветку с `origin/test-server`, проверяет также весь актуальный список, запускается в GitHub Actions для `feature/**` и pull request в TEST, а также останавливает TEST deploy до SSH и изменения сервера. Полный локальный аудит: 138 операций, 122 опубликованы, 16 обоснованно исключены, пропусков нет. Доски опубликованы как четыре READ-ресурса и восемь подтверждаемых действий через существующие исполнители. GitHub и TEST пока не менялись, статус CODE_ONLY.
