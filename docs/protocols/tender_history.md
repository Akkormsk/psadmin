#### Согласованный архив и компактная история — DECIDED_BACKLOG, 2026-11-14

Решение владельца: один архив с одинаковыми карточками и одной кнопкой восстановления; разделы определяются этапом выбытия (Входящие, оценка, расчёт, торги/результат, в дальнейшем исполнение), причина исключения хранится отдельно. Истечение срока — причина, а не отдельный дублирующий архив. Восстановление возвращает на прежний этап и сохраняет внутреннюю работу пользователя.

- Первичный поиск использует доступные параметры ГосПлана; вторичный отбор выполняется один раз при поступлении. Решение и сработавшие слова сохраняются. Обновление внешних сведений не должно заново исключать уже отобранные или восстановленные вручную карточки. Фоновая архивация по истечению срока остаётся. Изменение правил действует на новые поступления; повторный отбор старых — только по отдельной команде с понятными последствиями.
- Для отсеянного на входе тендера достаточно компактной текстовой записи. Открытие архивной записи показывает сохранённые сведения; подкачка полной карточки запускается при восстановлении. ЕИС восстанавливается по номеру извещения, не по названию; другие источники требуют своего адаптера. Недоступность внешнего сервиса явно показывается, не объявляется успешным восстановлением.
- Приложение сохраняет текстовые данные. Вложения загружаются из источника по явному клику/запросу чтения, используются временно и не сохраняются как постоянные бинарные копии или бинарные данные внутри HTML/base64; временные файлы удаляются после обработки, включая ошибки. Исходные ссылки и полученный текст можно сохранять. Это целевое поведение: существующий DocumentPreview ещё требует сверки/изменения, хранение только текста не объявлено реализованным.
- Одна каноническая таблица компактной истории: одна запись на `(источник, закон, номер закупки)`. Сохраняются название, сработавшие плюс/минус-слова и сочетания, версия применённых правил, этап, причина и автор решения (человек/автоматика), даты; при наличии достоверных фактов — результат участия, НМЦК, наша цена/место, итоговая цена, прогноз и факт снижения, размер выборки прогноза и источники этих сведений. Неизвестные значения пустые, не нули. Повторное получение не создаёт второй статистический пример.
- Назначение истории: оценка качества слов и предложения по отбору; накопление фактов торгов для прогноза и сравнения прогноза с результатом. Автоматическое скрытие/истечение срока не являются подтверждением «не наш профиль». Предложения по словам применяются только после выбора владельца. Ни риск 1875, ни неверный маршрут не превращаются в автоматически усвоенное правило из одного проигрыша.
- Перед удалением полной карточки переносится нужный компактный итог: нельзя потерять подтверждённую причину отказа из каскадно удаляемого feedback или сохранённый прогноз. Расчёты, комментарии, подтверждённые учебные примеры и данные незавершённого исполнения не уничтожаются вместе с уборкой пустой карточки. Повторно получить их из ЕИС невозможно.
- Таблица истории доступна в админке: поиск, фильтры по периоду/источнику/этапу/причине/типу решения, просмотр и удаление записей. Статистические сводки вычисляются из неё; после удаления не остаются скрытые дубли этих фактов в другом learning store. Сроки автоматической очистки и правила удаления связанной внутренней работы ещё не согласованы; ранее предложенные 30/90 дней не являются утверждёнными настройками.

Продуктовый жизненный цикл архива остаётся планом; структура пункта 1 уже TEST_VERIFIED выше. TenderHistory переиспользует таблицу IncomingTrace и содержит компактный итог; TenderDismissalFeedback остаётся источником текущих подтверждённых действий, собственные ContractStat связаны с историей для совместимости старого прогноза. Дальнейший переход потребителей не должен создавать параллельный реестр или считать рабочую карточку и её историю двумя примерами. Существующие предметные Lesson/ProductionTrainingExample и рабочие расчёты сохраняют свой контракт; технические журналы запросов не являются строками этой истории.

#### Фактическое использование накопленных данных — сверка TEST e96eeba и шага 1 на 03830b9, 2026-11-14

- `word_audit.py`: считает срабатывания слов на взятых в работу, подтверждённо отклонённых, проигнорированных и скрытых карточках/IncomingTrace; AI-аудит запускается по кнопке, предлагает add/remove plus/minus с последствиями, применяет выбор пользователя. Это не автоматически меняющий слова демон. В пункте 1 исключён двойной учёт: связанная история не считается вторым примером, после удаления рабочей карточки используется её оставшийся компактный итог.
- `_record_contract_stat` сохраняет результат из карточки в ContractStat, только когда известны итоговая цена и снижение. Запись переживает удаление Tender. `price_stats_for` использует только fz44 / own_funnel / forecast_included, исключает совместные закупки; источником являются завершённые закупки нашей воронки, в том числе без нашего участия. Категория и слова определяют похожесть, регион/дата — порядок примеров; рассматриваются до 2000 последних кандидатов. Основа подсказки — медиана снижения найденных аналогов, ограниченная настройками; при недостаточной выборке прогноза нет. Общерыночные строки own_funnel=False не участвуют.
- Прогноз и размер выборки сохраняются на Tender при создании расчёта; `_market_forecast_comparison` показывает отклонение факта от прогноза. Автоматической калибровки прогноза по прошлым ошибкам не найдено. В пункте 1 эти поля также сохраняются в независимой компактной истории и переживают удаление Tender; сама формула прогноза не менялась.
- Широкое обновление реестра контрактов через прямой ЕИС не подтверждено: `eis_source.contracts` явно возвращает ошибку; сохранённые данные доступны. Наличие расчёта статистики не доказывает свежесть/полноту всех фактов на серверах.
- Подтверждённые Lesson/ProductionTrainingExample и словарь AttributeConceptHint используются в подборе товаров/маршрутов/сопоставлении характеристик. Это подтверждённая обратная связь и знания, а не автоматические уроки из результата торгов. Автоматического статистического обучения оценки рисков по исходам закупок при сверке не найдено.
- PullRun/StatsRun и задания расчёта хранят результаты выполнения, ошибки, время и доступные оценки расхода: назначение — диагностика покрытия, надёжности и затрат, не обучение фильтра или прогноза. Runtime receipts учитывают фактические HTTP attempts отдельно от успешных страниц.
