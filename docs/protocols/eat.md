### ЕАТ «Берёзка» — интеграция входящих (CODE_ONLY, 2026-11-11)

TEST settings now distinguish source selection (EIS/EAT) and procurement laws from incoming title/profile filtering. Sources gate both EIS collection paths and EAT collection; disabling a source preserves its saved records. Incoming source dropdown is independent of ingestion. EAT no longer applies title words before persistence or treats session start as publication date, respects selected laws, and runs in the existing scheduler when EAT_PULL_ENABLED is enabled. EAT region/OKPD2 normalization and full historical published-window support remain incomplete and are stated on the settings screen. This release does not claim goods/document pipeline equivalence or launch paid AI/backfill.

Отдельная ветка `feature/eat-incoming-integration` от `test-server`: источник `eat` для существующей `Tender`, без самостоятельной витрины/жизненного цикла и без изменения `main`. ЕАТ использует Bearer token и номер организации 300911501 из TEST, никогда не сохраняет токен в Git/БД. При ручном «Обновить» одновременно запускаются независимые ГосПлан-подбор и read-only асинхронная выгрузка ЕАТ; EAT пишет собственный PullRun, не выполняет подачи предложений. Нормализуем только закупки с явно подтверждённым `typePurchase` по 44-ФЗ, от 300 тыс. ₽ (или общего порога), с плюс/минус-словами и актуальным сроком. Дубликаты не создаются, пользовательские решения при обновлении сохраняются, сведения ЕАТ не отправляются в API ЕИС. Временное наследование поля `eis_url` только как существующего поля внешней ссылки снабжено меткой ЕАТ в UI; отдельная сущность документов ещё не включена.

Изолированный запрос `requestOrderList` с корректным Bearer token подтверждён GitHub Actions 43045588384: HTTP 200, `processingResult=complete`, 675 сессий (55 от 300 тыс. ₽). Датированный запрос `requestOrdersListLitePublished` по XSD принят сервером (HTTP 200), но вернул `ProcessingState=error` (Actions 43049999426). Пока режим `published` не прошёл проверку, код явно помечает `active_only`: он не гарантирует полного исторического покрытия за N дней. Нет гарантии, что начало закупочной сессии равно дате публикации. Внешнее правовое основание подтверждено по `typePurchase` на отдельном read-only API вызове (Actions 43051911724). Блокировки: пробелы в определении региона/ОКПД2 и отсутствие полноценной нормализации вложений ЕАТ; их не маскировать.

Перед TEST_VERIFIED: проверить CI, POST кнопки и фон, ACTUAL TEST SHA/health, наличие `EAT_API_TOKEN` только в TEST env, отсутствие ЕИС-вызовов по новым сессиям и повторный импорт. До приёмки не разрешать PROD, массовую обработку документов/ИИ, ставки и платные запросы. Ветка сама по себе не равна релизу.
