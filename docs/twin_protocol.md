# Протокол: близнец (тест) и прод

Прод — https://admin.psodin.ru, близнец — https://test.admin.psodin.ru.
Оба на одном VDS (46.149.70.38, российский IP — ЕИС и банк доступны обоим).
У близнеца своя копия базы; прод он не видит и не трогает.

## Команды пользователя

| Команда | Что делает агент | Когда можно |
|---|---|---|
| **«на тест»** | Отправляет на близнеца текущий код из своей рабочей копии (включая незакоммиченное), пересобирает, применяет миграции к базе близнеца, проверяет, что он поднялся, и присылает ссылку. | В любое время |
| **«обнови тестовую базу»** | Затирает базу близнеца свежей копией рабочей базы и применяет к ней миграции текущего кода близнеца. | В любое время |
| **«запусти на тесте …»** (сбор тендеров, синк банка, риски и т. п.) | Разово запускает эту задачу на близнеце. Автозадачи на близнеце выключены всегда. | В любое время |
| **«деплой»** | Выкатывает на прод ровно ту версию, которая сейчас на близнеце: коммит в `main` → push → `deploy.sh` (бэкап базы → миграции → перезапуск → проверка). | Только после 20:00 МСК. Днём — только если пользователь явно сказал, что понимает, что сейчас день. |
| **«откати прод»** | Возвращает прод к предыдущей версии. Если в выкатке были миграции — предлагает восстановить базу из бэкапа, сделанного перед деплоем (данные, внесённые после деплоя, при этом теряются — агент сначала говорит, какие). | Сразу |

## Правила агента

1. На прод попадает только то, что было на близнеце и что пользователь посмотрел.
   Если после «на тест» код менялся — снова «на тест» перед «деплоем».
2. Перед «на тест» и «деплоем» агент прогоняет локальные тесты. Упавшие тесты — стоп и отчёт.
3. Близнец ходит в те же внешние сервисы (ЕИС, ГосПлан, Модульбанк — только чтение).
   Вызовы ИИ на близнеце тратят тот же бюджет, что и прод, поэтому агент запускает их точечно.
4. Прод агент не правит руками на сервере: только через `main` + `deploy.sh`.
5. База близнеца — одноразовая: её можно ломать, «обнови тестовую базу» вернёт её в рабочее состояние.

## Техника (для агента)

- Код близнеца: `~/psadmin-test`, заменяется целиком при каждом «на тест»:
  `git ls-files -co --exclude-standard -z | tar --null -cf - -T - | ssh deploy@46.149.70.38 '…распаковать в ~/psadmin-test…'`,
  затем `~/psadmin-test/deploy/vds/twin.sh up`.
- Настройки близнеца: `~/psadmin-test.env` (все `*_ENABLED=0`, своя база `test-db`).
- «обнови тестовую базу»: `~/psadmin-test/deploy/vds/twin.sh refresh-db`.
- Разовая задача: `docker compose -f ~/psadmin-test/deploy/vds/compose.test.yml run --rm -T test-web python manage.py <команда>`.
- Прод: `~/psadmin/deploy/vds/deploy.sh`.
