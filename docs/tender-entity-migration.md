# Единая сущность Tender

## Цель

`Tender` — единственный объект жизненного цикла закупки. Карточка, стадия,
документы ЕИС, оценка рисков, результат и тендерный расчёт принадлежат ему.

`TenderEstimate` — только расчёт конкретного `Tender`. Связь прямая:
`TenderEstimate.tender`. Расчёт не является самостоятельной карточкой канбана.

`OrderEstimate` — самостоятельный сохранённый расчёт заказа вне пайплайна.
У него нет и не будет ссылки на `Tender`: обычный заказ не должен становиться
фиктивным тендером. Механика расчёта и база знаний при этом общие.

`calculator.Estimate` — другое, независимое приложение калькулятора. Эта
миграция не меняет его таблицу, записи, маршруты или интерфейс.

## Что было до миграции

Данные ЕИС и состояние канбана жили в `FoundTender`. В нём же была обратная
ссылка `pushed_estimate`, хотя у `TenderEstimate` уже существовало прямое
поле `tender`. Из-за этого один тендер приходилось искать через два объекта.

## Что делает миграция

1. Переносит поля карточки и жизненного цикла из `FoundTender` в `Tender`.
2. Для каждой старой записи `FoundTender` заполняет соответствующий `Tender`.
3. Старые самостоятельные расчёты переносит в `OrderEstimate` вместе с
   позициями, итогами, владельцем и датами; исходная запись сохраняется как
   проверяемая историческая связь.
4. Переводит прикладной код, URL и канбан на `Tender`; старые ссылки на
   расчёты перенаправляются на перенесённый `OrderEstimate`.

Миграция только добавляет поля и связи. Она не удаляет ни одну строку
`FoundTender`, `TenderEstimate`, `TenderLine` или `calculator.Estimate`.
`FoundTender` остаётся временной исторической таблицей для обратимой
проверки переноса и не должна использоваться в новых маршрутах.

## Инварианты после миграции

- Любой новый тендерный расчёт имеет `TenderEstimate.tender_id`.
- Любой самостоятельный расчёт создаётся как `OrderEstimate`, без `Tender`.
- Карточка `/tender-selection/<pk>/` принимает `Tender.pk`.
- Канбан строится только из `Tender` и его `estimates`.
- Импорт ЕИС обновляет `Tender` по паре `(law, purchase_number)`.
- Сохранённые расчёты приложения `/tenders/` не участвуют в тендерном
  пайплайне и не видны в «Тендерах».

## Как проверять перед выпуском

1. Выполнить миграции на копии БД.
2. Сверить: количество `FoundTender` и `Tender` с данными ЕИС; количество
   `TenderEstimate` без `tender_id` должно быть нулём.
3. Открыть старую карточку, ручной расчёт, расчёт из ЕИС, торги и архив.
4. Проверить вход под менеджером: доступны только прежние маршруты расчётов,
   раздел `/tender-selection/` закрыт.
