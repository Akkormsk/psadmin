# Протокол PSADMIN — главный индекс

## Назначение и общая архитектура

PSADMIN ведёт тендер от ЕИС/ГосПлана через отбор/документы/расчёт до торгов и результата. Полная калькуляция V2 и исполнение ещё не приняты. LLM интерпретирует язык, backend валидирует источники, считает, фильтрует и ранжирует. V1 сохраняется до принятия V2; никаких supplier/product hardcodes.

Источники истины для кода и операционных данных — GitHub и Timeweb PostgreSQL соответственно. Сущности и сервисы Django переиспользуются; параллельные реестры тендеров, знаний и AI-only расчётчики не создаются. UI, общий ассистент и будущий Telegram используют общий backend executor.

Архитектура V2: тендер → исходные позиции → рабочие позиции → компоненты → маршруты и операции → подтверждённый исполнитель/версия знаний → сохранённый расчёт. Наличие моделей и доставка кода не доказывают приёмку полного цикла. Подробный контракт — в доменных протоколах.

## Глобальные инварианты

- Правила разработки — [AGENTS.md](../AGENTS.md). Работа ведётся в `feature/*` и TEST. PROD, deploy, разрушительные операции, массовые AI/backfill и платные запуски требуют предусмотренного явного разрешения владельца.
- TEST и PROD изолированы. Push в `test-server` запускает TEST deploy; push в `main`, включая документацию, запускает PROD release. Ограничения и проверка фактического SHA — в [протоколе окружений](protocols/operations.md).
- LLM интерпретирует язык; backend валидирует источники, права и ссылки, выполняет математику, фильтрацию и ранжирование. Пользовательские ACTION используют общий с UI executor, preview/подтверждение, идемпотентность и аудит.
- Неизвестное не равно нулю, отсутствию факта или готовности. Частичный результат, fallback и успешная доставка не доказывают полноту или семантическую приёмку.
- Сохраняются исходные сведения, происхождение, подтверждённые решения и воспроизводимость версий. Обновление внешних данных не отменяет ручную работу молча.
- Статусы `PROD_VERIFIED`, `TEST_VERIFIED`, `CODE_ONLY`, `DECIDED_BACKLOG`, `DEFERRED`, `REJECTED` сохраняют свой смысл и область подтверждения. Проверенный application release и HEAD документов различаются; SHA развёртывания не выдумывается.
- Датированные приёмки и решения читаются вместе с последующими уточнениями соответствующего домена. Исторические разрешения и бюджеты не являются новым разрешением запуска.
- Читать и обновлять протокол соответствующего домена; новый результат дополняет его контракт, а не создаёт параллельную методичку. История сопровождения и архивные SHA — в [отдельном разделе](protocols/maintenance.md).

Git не хранит production-базу, выгрузки поставщиков, документы заказчиков и секреты.
